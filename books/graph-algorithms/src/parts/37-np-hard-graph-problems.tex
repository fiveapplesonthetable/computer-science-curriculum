\chapter{NP-Hard Graph Problems and Reductions}
\label{ch:np-hard}

Through the first thirty-six chapters, every algorithm ran in \emph{polynomial time}, meaning its step count was bounded by $\Oh(n^c)$ for some fixed constant $c$ as a function of the input size $n$: breadth-first search, Dijkstra's algorithm, network flows, matchings, spectral partitioning, and PageRank iterations all stayed within polynomial bounds. For many natural graph problems, however, no polynomial-time algorithm is known, and complexity theory gives strong evidence that none exists.

These hard problems are linked to one another. A polynomial-time algorithm for
any one of them would yield polynomial-time algorithms for all of them, and
for thousands of other problems as well. The link comes from
\emph{reductions}: fast algorithms that translate an input of one problem into an equivalent input of another. Building
and reading reductions lets you tell whether a new problem can be solved fast and exact,
or whether you should settle for a provably near-optimal answer (approximation), restrict the exponential cost to a small parameter (parameterization, Chapter~25), or use practical rules of thumb without worst-case guarantees (heuristics).

The companion algorithms book introduced the complexity classes $\mathsf{P}$ (problems solvable in polynomial time) and $\mathsf{NP}$ (problems whose solutions can be verified in polynomial time), along with $\mathsf{NP}$-completeness. We review those definitions briefly and apply them to graphs.

\section{What Hardness Means}
\label{ch37:meaning}

Complexity theory works with \emph{decision problems}: questions whose answer is yes or no. For a graph $\Gph$ and an integer $k$, ``Does
$\Gph$ have a matching of size $\ge k$?'' is a decision problem; ``What is the
size of a largest matching in $\Gph$?'' is the corresponding optimization problem. Decision problems are convenient
because yes/no answers compose cleanly when translating one problem into another, and
finding an optimal value $k$ on an $n$-vertex graph usually reduces to $\Oh(\log n)$ decision
queries via binary search on $k$.

\begin{definition}[The class $\mathsf{NP}$]
\label{ch37:def-np}
A decision problem $\Pi$ belongs to $\mathsf{NP}$ (nondeterministic polynomial time) if there is a deterministic polynomial-time algorithm $V$, called a
\emph{verifier}, and a polynomial $p$ such that for every input $x$,
\[
   x \text{ is a yes-instance of } \Pi
   \quad\Longleftrightarrow\quad
   \text{there exists } w \text{ with } \abs{w}\le p(\abs{x}) \text{ and } V(x,w)=\text{accept}.
\]
Here a \emph{yes-instance} is an input whose true answer is yes, a \emph{no-instance} is an input whose true answer is no, $\abs{x}$ is the bit-length of $x$, and the string $w$ is called a \emph{certificate} (or \emph{witness}) for $x$. For a no-instance $x$, no string $w$ may cause $V(x,w)$ to accept.
\end{definition}

\begin{intuitionbox}
$\mathsf{NP}$ is the class of decision problems where every \emph{yes} answer has a short,
checkable proof. If someone claims $\Gph$ has a Hamiltonian cycle (a cycle visiting every vertex exactly once), they hand you the cyclic
order of the vertices; you verify in linear time that consecutive vertices share an edge
and that every vertex appears once. You do not have to find the cycle,
only check the proposed one. Finding a witness appears hard; checking one is fast.
The $\mathsf{P}$ versus $\mathsf{NP}$ question asks whether ``fast to check''
always implies ``fast to find.''
\end{intuitionbox}

Every problem in $\mathsf{P}$ is also in $\mathsf{NP}$ ($\mathsf{P}\subseteq\mathsf{NP}$): if you can solve an instance in polynomial time, a verifier can ignore the certificate $w$ and solve $x$ from scratch. Whether the inclusion is strict is open; most computer scientists expect $\mathsf{P}\neq\mathsf{NP}$, meaning some problems with fast verifiers admit no polynomial-time solver, though no proof is known.

\begin{definition}[Polynomial-time many-one reduction]
\label{ch37:def-reduction}
A decision problem $A$ \emph{reduces} to a decision problem $B$ in polynomial time, written $A\le_p B$, if there is a
polynomial-time computable function $f$ mapping each instance $x$ of $A$ to a single instance $f(x)$ of
$B$ (called ``many-one'' because distinct inputs $x_1,x_2$ may map to the same output) such that
\[
   x \text{ is a yes-instance of } A
   \quad\Longleftrightarrow\quad
   f(x) \text{ is a yes-instance of } B.
\]
\end{definition}

Read $A\le_p B$ as ``$A$ is no harder than $B$, up to a polynomial translation step'' (Figure~\ref{ch37:fig-reduction-pipeline}). If
$B$ has a polynomial-time algorithm, running $f$ and feeding $f(x)$ to $B$'s solver decides $A$ in polynomial
time. Reading that implication in reverse (its contrapositive) gives our main tool: if $A$ has no polynomial-time algorithm, then neither does $B$. Reductions carry hardness \emph{forward} along the arrow ($A\to B$) and
tractability \emph{backward} ($B\to A$).

\begin{trapbox}
The direction trips up beginners regularly. To prove a new problem $B$ is
hard, reduce a \emph{known}-hard problem $A$ \emph{to} $B$ ($A\le_p B$), showing
$B$ is at least as hard as $A$. Reducing
$B$ to $A$ ($B\le_p A$) proves nothing about $B$'s hardness: it shows only that $B$ is no harder than $A$. Remember: reduce \emph{from} the known hard problem \emph{to} your target.
\end{trapbox}

\begin{definition}[$\mathsf{NP}$-hard and $\mathsf{NP}$-complete]
\label{ch37:def-npc}
A problem $B$ is \emph{$\mathsf{NP}$-hard} if $A\le_p B$ for every $A\in
\mathsf{NP}$. It is \emph{$\mathsf{NP}$-complete} if both $B$ is $\mathsf{NP}$-hard and $B\in
\mathsf{NP}$. The $\mathsf{NP}$-complete problems are the hardest problems in
$\mathsf{NP}$: a polynomial-time algorithm for any one of them would imply
$\mathsf{P}=\mathsf{NP}$.
\end{definition}

\begin{marginnotebox}
Stephen Cook (1971) and Leonid Levin (1973) proved the first $\mathsf{NP}$-completeness theorem by encoding idealized step-by-step computer programs (Turing-machine verifiers) as logical AND/OR/NOT formulas; Richard Karp (1972) then reduced satisfiability to $21$ combinatorial problems (\S\ref{ch37:history}).
\end{marginnotebox}

Reductions are transitive: if $A\le_p B$ via $f$ and $B\le_p C$ via $g$, then $A\le_p C$ via $g\circ f$, because a polynomial of a polynomial is still a polynomial. Once
\emph{one} problem $A_0$ is proved $\mathsf{NP}$-hard from scratch, we never need to reduce from every problem in $\mathsf{NP}$ again: showing $A_0 \le_p B$ suffices to make $B$ $\mathsf{NP}$-hard as well. Our starting problem $A_0$ will be \textsc{3-SAT}, a logical satisfiability problem defined in the next section.

\begin{focusbox}
\textbf{Two-step template for proving a problem $B$ is $\mathsf{NP}$-complete.}
\begin{enumerate}
  \item \textbf{Membership ($B\in\mathsf{NP}$):} Specify a short certificate $w$ for a yes-instance and check in polynomial time that $w$ is valid.
  \item \textbf{Hardness ($A\le_p B$):} Pick a known $\mathsf{NP}$-complete problem $A$, build an instance $f(x)$ of $B$ in polynomial time, and prove \emph{both} directions: if $x$ is a yes-instance of $A$ then $f(x)$ is a yes-instance of $B$, and conversely.
\end{enumerate}
\end{focusbox}

\section{The Anchor: 3-SAT}
\label{ch37:3sat}

A \emph{Boolean variable} $x_i$ takes the value $\text{true}$ or $\text{false}$. A \emph{literal} is either a variable $x_i$ or its negation $\bar{x}_i$ (read ``not $x_i$,'' which is true exactly when $x_i$ is false). A \emph{clause} combines literals with logical OR ($\vee$), so it is true when at least one of its literals is true; a formula in \emph{conjunctive normal form} (CNF) combines clauses with logical AND ($\wedge$), so it is true when \emph{every} clause is true. For example,
\[
  \varphi = (x_1 \vee \bar{x}_2 \vee x_3) \wedge (\bar{x}_1 \vee x_2 \vee \bar{x}_3)
\]
is a CNF formula with two clauses on three variables, satisfied by setting $x_1 = x_2 = x_3 = \text{true}$. The decision problem \textsc{3-SAT} asks: given a CNF formula $\varphi$ with three literals per clause, is there a truth assignment to the variables that makes every clause true?

\begin{theorem}[Cook--Levin, 3-SAT form]
\label{ch37:thm-3sat}
\textsc{3-SAT} is $\mathsf{NP}$-complete.
\end{theorem}

We take the hardness half of Theorem~\ref{ch37:thm-3sat} from the companion book and check membership:
$\textsc{3-SAT} \in \mathsf{NP}$ because a truth assignment to the $n$ variables is an $n$-bit certificate
whose $m$ clauses can be evaluated in $\Oh(n+m)$ time. Every hardness proof below is a \emph{gadget
construction} that turns variables and clauses of $\varphi$ into small subgraphs.

\begin{intuitionbox}
A reduction from \textsc{3-SAT} has two parts. \emph{Variable gadgets}
force a binary choice (true or false) for each variable. \emph{Clause gadgets}
check that at least one literal in each clause is true, wired to the
variable gadgets so they respect those choices. Each gadget enforces a local constraint, and the global graph object we ask for (a large independent set, a proper coloring, or a Hamiltonian cycle)
exists if and only if all local constraints are met at once,
which happens exactly when $\varphi$ is satisfiable.
\end{intuitionbox}

\section{Independent Set, Vertex Cover, and Clique}
\label{ch37:isvc}

These three problems translate directly into one another (Chapter~29). Fix an undirected graph $\Gph=(V,E)$ on $n=\abs{V}$ vertices and an integer $k$:

\begin{itemize}
  \item An \emph{independent set} is a subset $S\subseteq V$ containing no two adjacent vertices.
        \textsc{Independent-Set}: is there one of size $\ge k$?
  \item A \emph{vertex cover} is a subset $C\subseteq V$ touching every edge (each
        edge has at least one endpoint in $C$). \textsc{Vertex-Cover}: is there
        one of size $\le k$?
  \item A \emph{clique} is a subset $K\subseteq V$ in which every two vertices share an edge.
        \textsc{Clique}: is there one of size $\ge k$?
\end{itemize}

\begin{lemma}[The complementarity triangle]
\label{ch37:lem-triangle}
For any graph $\Gph=(V,E)$ on $n$ vertices and any subset $S\subseteq V$:
\begin{enumerate}
  \item $S$ is an independent set in $\Gph$ if and only if $V\setminus S$ (the vertices outside $S$) is a vertex cover of
        $\Gph$.
  \item $S$ is an independent set in $\Gph$ if and only if $S$ is a clique in the complement graph
        $\overline{\Gph}$ (the graph on $V$ where distinct vertices share an edge exactly when they do not share one in $\Gph$).
\end{enumerate}
Hence the three decision questions are equivalent:
\begin{align*}
  \Gph \text{ has an independent set of size } \ge k
  &\Longleftrightarrow \Gph \text{ has a vertex cover of size } \le n-k \\
  &\Longleftrightarrow \overline{\Gph} \text{ has a clique of size } \ge k.
\end{align*}
\end{lemma}

\begin{proof}
For (1), $S$ is independent when no edge has both endpoints in $S$, which is the same as saying every edge has at least one endpoint in $V\setminus S$, meaning $V\setminus S$ covers every edge. For (2), distinct vertices $u,v\in S$ lack an edge in $\Gph$ if and only if they share an edge in $\overline{\Gph}$, so $S$ is edge-free in $\Gph$ if and only if $S$ is a clique in $\overline{\Gph}$.
Since $\abs{V\setminus S}=n-\abs{S}$ and building $\overline{\Gph}$ takes $\Oh(n^2)$ time, both equivalences are polynomial-time reductions.
\end{proof}

Complementing the vertex set or complementing the edge set converts any one of these three problems into the other two. Figure~\ref{ch37:fig-triangle-duality} shows both transformations on a four-vertex graph. Proving one $\mathsf{NP}$-complete proves all three $\mathsf{NP}$-complete; we prove \textsc{Independent-Set} by reducing from \textsc{3-SAT}.

\subsection{The gadget}

\begin{theorem}
\label{ch37:thm-is}
\textsc{Independent-Set} is $\mathsf{NP}$-complete.
\end{theorem}

\begin{proof}
Membership: a subset of $k$ vertices is a certificate whose pairwise non-adjacency can be checked
in $\Oh(k^2)$ time. Hardness: reduce from \textsc{3-SAT}. Let $\varphi$ have $m$
clauses $C_1,\dots,C_m$, each with three literals. Build a graph $\Gph_\varphi$ (Figure~\ref{ch37:fig-is}):

\begin{itemize}
  \item \textbf{Clause triangles.} For each clause $C_j=(\ell_{j1}\vee
        \ell_{j2}\vee \ell_{j3})$, create three vertices, one per literal
        occurrence, and join them in a triangle. Because all three vertices in a triangle are adjacent, an independent set can contain at most one of them, selecting at most one
        satisfying literal per clause.
  \item \textbf{Conflict edges.} For every pair of literal vertices in $\Gph_\varphi$ that are
        \emph{negations} of each other ($x_i$ in one clause and $\bar{x}_i$ in
        another), add an edge between them. This forbids choosing both $x_i$ and $\bar{x}_i$,
        keeping the selected literals consistent with a single truth assignment.
\end{itemize}

Set $k=m$. As verified in the box below, $\varphi$ is satisfiable if and only if $\Gph_\varphi$ has an
independent set of size $m$.
\end{proof}

\begin{whybox}
\textbf{Why the construction is correct.}
($\Rightarrow$) Suppose $\varphi$ has a satisfying assignment. Each clause has at least one true
literal; pick one true literal vertex from each of the $m$ triangles. No two chosen vertices share a triangle edge (they lie in different triangles), and no two share a dashed conflict edge (that would mean both $x_i$ and $\bar{x}_i$ are true under the same assignment, which is impossible). Thus the
$m$ chosen vertices form an independent set.

($\Leftarrow$) Conversely, let $S$ be an independent set of size $m$. Each triangle contains at
most one vertex of $S$, and there are $m$ disjoint triangles, so $S$ contains \emph{exactly}
one vertex per triangle. Set each chosen literal to true
(if a vertex labeled $x_i$ is in $S$, set $x_i=\text{true}$; if a vertex labeled $\bar{x}_i$ is in $S$, set
$x_i=\text{false}$). Because $S$ contains no conflict edge, no variable is assigned both
true and false. Any variable not appearing in $S$ can be set arbitrarily (say to false). Every clause contains one chosen literal,
so every clause evaluates to true and $\varphi$ is satisfied.
\end{whybox}

The graph $\Gph_\varphi$ has $3m$ vertices and at most $\binom{3m}{2}$ edges, so constructing it takes
$\Oh(m^2)$ time. By Lemma~\ref{ch37:lem-triangle},
\textsc{Vertex-Cover} and \textsc{Clique} are $\mathsf{NP}$-complete as well.

\begin{labbox}
Trace $\varphi=(x_1\vee x_2\vee x_3)\wedge(\bar{x}_1\vee\bar{x}_2\vee x_3)$
in Figure~\ref{ch37:fig-is}, where $k=m=2$. Under the assignment $x_3=\text{true}$ (with $x_1,x_2$ arbitrary), pick the $x_3$
vertex in $C_1$ and the $x_3$ vertex in $C_2$. No triangle edge joins them, and no
conflict edge joins them because both carry the same literal $x_3$ rather than opposite literals. Writing $x_3^{(1)}$ and $x_3^{(2)}$ for the two copies, $\{x_3^{(1)}, x_3^{(2)}\}$ is another independent set of size $2$, confirming that setting $x_3=\text{true}$ alone satisfies both clauses. By contrast, picking $x_1$ in $C_1$ and $\bar{x}_1$ in $C_2$ violates the top dashed conflict edge.
\end{labbox}

\begin{algorithm}[htbp]
\caption{\textsc{Reduce-3SAT-to-IndependentSet}$(\varphi)$}
\label{ch37:alg-is}
\DontPrintSemicolon
\KwIn{CNF formula $\varphi$ with clauses $C_1,\dots,C_m$, three literals each.}
\KwOut{Graph $\Gph$ and integer $k$ such that $\varphi$ is satisfiable if and only if $\Gph$ has an independent set of size $\ge k$.}
$V\gets\emptyset$;\quad $E\gets\emptyset$\;
\ForEach{clause $C_j=(\ell_{j1}\vee\ell_{j2}\vee\ell_{j3})$}{
  create vertices $v_{j1},v_{j2},v_{j3}$ labeled by the literals\;
  add triangle edges $\{v_{j1}v_{j2}, v_{j2}v_{j3}, v_{j3}v_{j1}\}$ to $E$\;
}
\ForEach{pair $u,v$ with $\mathrm{label}(u)=x_i,\ \mathrm{label}(v)=\bar{x}_i$}{
  add edge $uv$ to $E$ \tcp*{conflict edge}
}
$k\gets m$\;
\Return $(\Gph=(V,E),\,k)$\;
\end{algorithm}

\begin{complexitybox}
Algorithm~\ref{ch37:alg-is} runs in $\Oh(m^2)$ time and builds $\Oh(m)$ vertices and $\Oh(m^2)$ edges.
Consequently, \textsc{Independent-Set}, \textsc{Vertex-Cover}, and
\textsc{Clique} are $\mathsf{NP}$-complete. Exhaustive subset search takes $\Oh(2^n\cdot\poly(n))$ time (where $\poly(n)$ denotes a polynomial factor in $n$), which recursive branching on high-degree vertices (Chapter~25) improves to roughly $\Oh(1.2^n)$ for \textsc{Independent-Set}.
\end{complexitybox}

\section{Graph Coloring}
\label{ch37:coloring}

A \emph{proper $c$-coloring} assigns each vertex one of $c$ colors so that
adjacent vertices receive different colors (Chapter~28). \textsc{$c$-Coloring} asks: can $\Gph$ be properly colored
with $c$ colors? The \emph{chromatic number} $\chi(\Gph)$ is the smallest $c$ for which a proper $c$-coloring exists.

Coloring with $c=2$ colors takes linear time (\S\ref{ch37:boundary}); for $c=3$, the problem becomes $\mathsf{NP}$-complete.

\begin{theorem}
\label{ch37:thm-3col}
\textsc{3-Coloring} is $\mathsf{NP}$-complete.
\end{theorem}

\begin{proof}[Construction]
Membership: a proposed coloring is a certificate checkable in $\Oh(n+m)$ time by scanning all edges. Hardness:
reduce from \textsc{3-SAT}. Call the three colors $\mathsf{T}$ (true), $\mathsf{F}$ (false), and $\mathsf{B}$
(base). The graph combines three kinds of gadgets (Figure~\ref{ch37:fig-3col}).

\textbf{Palette triangle.} Create three vertices $T,F,B$ joined in a triangle.
In any proper 3-coloring they receive three distinct colors; by relabeling colors, assume $T$ gets $\mathsf{T}$,
$F$ gets $\mathsf{F}$, and $B$ gets $\mathsf{B}$.

\textbf{Variable gadget.} For each variable $x_i$, create two vertices $x_i$ and $\bar{x}_i$
joined to each other and both joined to $B$. Because $B$ has color $\mathsf{B}$, the triangle $\{x_i,\bar{x}_i,B\}$
forces $\{x_i,\bar{x}_i\}$ to receive $\{\mathsf{T},\mathsf{F}\}$ in one of the two orders, encoding a truth assignment to $x_i$.

\textbf{Clause gadget (two chained OR-gadgets).} A binary OR-gadget on input vertices
$p,q$ adds a triangle $\{u_p,u_q,r\}$ with $u_p$ adjacent to $p$, $u_q$ adjacent to $q$, and output vertex $r$. For each clause $(a\vee b\vee c)$, chain two binary OR-gadgets: the first combines $a$ and $b$ into intermediate vertex $r_1$ via triangle $\{u_a,u_b,r_1\}$, and the second combines $r_1$ and $c$ into clause-output vertex $r_2$ via triangle $\{u_{r_1},u_c,r_2\}$. Finally, join $r_2$ to both $F$ and $B$. As checked below, the whole graph is 3-colorable if and only if $\varphi$ is satisfiable.
\end{proof}

\begin{whybox}
\textbf{Why the OR-gadget works.} In a binary OR-gadget on inputs $p,q\in\{\mathsf{T},\mathsf{F}\}$ with triangle $\{u_p,u_q,r\}$:
\begin{itemize}
  \item If $p=q=\mathsf{F}$, both $u_p$ and $u_q$ are forbidden from color $\mathsf{F}$, so the edge $u_pu_q$ forces $\{u_p,u_q\}=\{\mathsf{T},\mathsf{B}\}$, leaving $r=\mathsf{F}$ as the only choice for the third triangle vertex.
  \item If $p=\mathsf{T}$ (whether $q$ is $\mathsf{T}$ or $\mathsf{F}$), coloring $u_p=\mathsf{F}$ and $u_q=\mathsf{B}$ is valid because $q\neq\mathsf{B}$, leaving $r=\mathsf{T}$ available (Figure~\ref{ch37:fig-3col}, first triangle). The case $q=\mathsf{T}$ is symmetric.
\end{itemize}
Thus $r$ can take color $\mathsf{T}$ if and only if at least one of $p,q$ has color $\mathsf{T}$, and when $p=q=\mathsf{F}$, $r$ is forced to $\mathsf{F}$. Chaining two binary OR-gadgets extends this rule to three inputs $a,b,c$: if $a=b=c=\mathsf{F}$, then $r_1=\mathsf{F}$ and hence $r_2=\mathsf{F}$, colliding with the edge from $r_2$ to $F$; if at least one of $a,b,c$ is $\mathsf{T}$, we can color $r_2=\mathsf{T}$, which avoids both $F$ (color $\mathsf{F}$) and $B$ (color $\mathsf{B}$). Hence the graph is 3-colorable if and only if $\varphi$ has a satisfying assignment.
\end{whybox}

The graph has $3 + 2n + 6m = \Oh(n+m)$ vertices and $\Oh(n+m)$ edges, built in linear time.
\textsc{3-Coloring} is therefore $\mathsf{NP}$-complete, and for every fixed $c\ge 3$,
\textsc{$c$-Coloring} is $\mathsf{NP}$-complete as well: adding a clique of $c-3$ new vertices, each joined to every vertex of the 3-coloring instance, uses up $c-3$ colors and leaves $3$ colors for the original graph (Exercise~\ref{ch37:ex-clift}).

\begin{applicationbox}
Register allocation in compilers is graph coloring (Chapter~28): vertices are program
variables simultaneously live, edges join variables that cannot share a CPU register, and colors
are physical registers. Frequency assignment for radio towers, exam scheduling
(colors are time slots, edges are shared-student conflicts), and Sudoku (extending a partially colored
81-vertex conflict graph to a proper 9-coloring) are also graph-coloring problems. Because exact coloring is
$\mathsf{NP}$-hard, production compilers use Chaitin--Briggs heuristics, coloring low-degree vertices greedily and \emph{spilling} uncolorable variables to main memory.
\end{applicationbox}

\section{Hamiltonian Cycle and the Traveling Salesman}
\label{ch37:ham-tsp}

A \emph{Hamiltonian cycle} visits every vertex of $\Gph$ exactly once and returns to its starting vertex.
\textsc{Ham-Cycle} asks whether $\Gph$ contains one. Contrast this with an
\emph{Eulerian circuit} (Chapter~5), which traverses every \emph{edge} once and can be tested in
linear time: a connected undirected graph has an Eulerian circuit if and only if every vertex has even degree.
Replacing ``every edge'' with ``every vertex'' turns a linear-time check into an
$\mathsf{NP}$-complete search, because no local degree test characterizes whether a global vertex-visiting cycle exists.

\begin{marginnotebox}
The Hamiltonian cycle is named after William Rowan Hamilton's 1857 ``Icosian Game'' on the $20$ vertices of a dodecahedron. Euler's 1736 Seven Bridges problem (visiting every edge) takes linear time; Hamilton's problem (visiting every vertex) is $\mathsf{NP}$-complete.
\end{marginnotebox}

\begin{theorem}
\label{ch37:thm-ham}
\textsc{Ham-Cycle} (in both directed and undirected graphs) is $\mathsf{NP}$-complete.
\end{theorem}

\begin{proof}[Sketch with the key gadget]
Membership: the cyclic vertex sequence is a certificate checkable in $\Oh(n)$ time.
Hardness: reduce from \textsc{3-SAT} to directed \textsc{Ham-Cycle}. (To reduce directed \textsc{Ham-Cycle} to undirected \textsc{Ham-Cycle}, replace each directed vertex $u$ with a three-vertex path $u^{\mathrm{in}}\text{--}u^{\mathrm{mid}}\text{--}u^{\mathrm{out}}$, turning each arc $u\to w$ into an undirected edge $u^{\mathrm{out}}w^{\mathrm{in}}$; since $u^{\mathrm{mid}}$ has degree $2$, any Hamiltonian cycle must pass straight through $u^{\mathrm{in}}\text{--}u^{\mathrm{mid}}\text{--}u^{\mathrm{out}}$ without reversing.)

\textbf{Variable chains.} For each variable $x_i$ ($1\le i\le n$), build a horizontal chain of $2m$
vertices $v_{i,1},\dots,v_{i,2m}$ with directed arcs in both directions between consecutive vertices. Connect the ends of chain $x_i$ to both ends of chain $x_{i+1}$ (with a source vertex $s$ at the top and a sink vertex $t$ looping back to $s$) so any Hamiltonian cycle must traverse each chain $x_i$ end-to-end in one direction: left-to-right encodes $x_i=\text{true}$, and right-to-left encodes $x_i=\text{false}$.

\textbf{Clause vertices.} For each clause $C_j$ ($1\le j\le m$), add a single vertex $c_j$ and reserve the pair $(v_{i,2j-1}, v_{i,2j})$ on each variable's chain for $C_j$. If $x_i$ appears positively in $C_j$, add detour arcs $v_{i,2j-1}\to c_j\to v_{i,2j}$ (Figure~\ref{ch37:fig-ham}); if $\bar{x}_i$ appears in $C_j$, reverse the detour to $v_{i,2j}\to c_j\to v_{i,2j-1}$. The cycle can detour through $c_j$ without stranding vertices if and only if at least one literal of $C_j$ is traversed in its satisfying direction.
\end{proof}

Hamiltonicity reduces immediately to the Traveling Salesman Problem (\textsc{TSP}).

\begin{definition}[Traveling Salesman Problem]
\label{ch37:def-tsp}
\textsc{TSP}: given $n$ cities, symmetric nonnegative pairwise distances $d(i,j)$, and a budget $L$, is
there a tour visiting every city once and returning to its start with total length $\le L$?
\end{definition}

\begin{theorem}
\label{ch37:thm-tsp}
\textsc{TSP} is $\mathsf{NP}$-complete, even in the \emph{metric} case where
distances obey the triangle inequality $d(i,k)\le d(i,j)+d(j,k)$ for all $i,j,k$ (going directly is never longer than detouring through a third city).
\end{theorem}

\begin{proof}
Membership: a tour is an $n$-city permutation whose total length can be summed and compared against $L$ in $\Oh(n)$ time. Hardness: reduce undirected \textsc{Ham-Cycle} to metric \textsc{TSP} (Figure~\ref{ch37:fig-tsp-reduction}). Given $\Gph=(V,E)$ on $n$ vertices, form the complete graph on $V$ with distances
\[
  d(i,j)=\begin{cases} 1 & \text{if } \{i,j\}\in E,\\ 2 & \text{if } \{i,j\}\notin E,\end{cases}
\]
for distinct $i,j$, and set the budget $L=n$. Every distance between distinct cities is $1$ or $2$, so the triangle inequality holds for all $i,j,k$:
\[
  d(i,k) \le 2 = 1 + 1 \le d(i,j) + d(j,k).
\]
Any tour uses $n$ edges, each of length at least $1$. Thus a tour has total length $\le n$ if and only if all $n$ of its edges have weight $1$, meaning every step traverses an actual edge of $\Gph$ and forms a Hamiltonian cycle. Constructing the $n\times n$ distance matrix takes $\Oh(n^2)$ time.
\end{proof}

\begin{trapbox}
A \emph{$\rho$-approximation algorithm} ($\rho\ge 1$) for a minimization problem runs in polynomial time and always returns a solution of cost at most $\rho$ times the optimum. Although metric \textsc{TSP} and general \textsc{TSP} (where distances need not obey the triangle inequality) are both $\mathsf{NP}$-complete, their approximability differs sharply. In general \textsc{TSP}, set $d(i,j)=1$ for edges of $\Gph$ and $d(i,j)=n\rho+1$ for non-edges: if $\Gph$ has a Hamiltonian cycle, the optimal tour costs $n$, so a $\rho$-approximation must return a tour of cost $\le n\rho$; if $\Gph$ has no Hamiltonian cycle, every tour uses at least one non-edge and $n-1$ other edges, costing at least $(n\rho+1)+(n-1) > n\rho$. Thus a polynomial-time $\rho$-approximation for general \textsc{TSP} would decide \textsc{Ham-Cycle}, ruling out \emph{any} constant-factor approximation unless $\mathsf{P}=\mathsf{NP}$. Metric \textsc{TSP}, by contrast, admits Christofides' $3/2$-approximation (Chapter~38) because the triangle inequality forbids making non-edges arbitrarily heavy.
\end{trapbox}

\section{Longest Simple Path}
\label{ch37:longest}

Shortest paths with nonnegative edge weights were solved in polynomial time in Chapters~7--9 (BFS, Dijkstra, Bellman--Ford, and Floyd--Warshall). By contrast, \textsc{Longest-Path} asks: given $\Gph$ and an integer $k$, is
there a \emph{simple} path (a path with no repeated vertices) of at least $k$ edges?

\begin{theorem}
\label{ch37:thm-longest}
\textsc{Longest-Path} is $\mathsf{NP}$-complete, even on unweighted graphs.
\end{theorem}

\begin{proof}
Membership: a sequence of distinct adjacent vertices of length $\ge k$ is checkable in $\Oh(n)$ time. Hardness: reduce from
\textsc{Ham-Path}, which asks for a simple path visiting all $n$ vertices (proved $\mathsf{NP}$-complete by the gadget of Theorem~\ref{ch37:thm-ham} without the return arc from $t$ to $s$). A graph
on $n$ vertices has a Hamiltonian path if and only if it has a simple path with at least $n-1$
edges. Setting $k=n-1$ leaves the graph unchanged and runs in $\Oh(1)$ time.
\end{proof}

\begin{whybox}
\textbf{Why does ``longest'' break what ``shortest'' kept?} The culprit is the requirement that the path be
\emph{simple}. With nonnegative edge weights, shortest walks never benefit from repeating a vertex, so shortest paths are simple automatically. Their prefixes are also shortest paths (\emph{optimal substructure}), which lets dynamic programming (DP) compute distances vertex by vertex.

Longest \emph{simple} paths violate optimal substructure (Figure~\ref{ch37:fig-longest-substructure}): the longest simple path from $s$ to $v$ passing through $u$ need not start with the longest simple path from $s$ to $u$, because a long prefix can consume a vertex needed later in the suffix. Dropping the no-repeat rule does not help either: in any graph with a reachable cycle, a longest \emph{walk} (which may repeat vertices) loops around the cycle forever to length $+\infty$. This mirrors how negative-weight cycles send shortest walks to $-\infty$ (Chapter~7).
\end{whybox}

\end{intuitionbox}

\section{Max-Cut and Steiner Tree}
\label{ch37:maxcut-steiner}

\textbf{Max-Cut.} Partition the vertex set $V$ into $(S,\bar{S})$, where $\bar{S}=V\setminus S$ is the set of vertices outside $S$, to maximize the number of edges
with one endpoint in $S$ and one in $\bar{S}$. \textsc{Max-Cut} asks: is there a cut crossing at least $k$ edges? Its minimization counterpart,
\textsc{Min-Cut} (Chapters~11--12), is solvable in polynomial time via maximum flow.

\begin{theorem}
\label{ch37:thm-maxcut}
\textsc{Max-Cut} is $\mathsf{NP}$-complete.
\end{theorem}

\begin{proof}[Idea]
Membership: checking how many edges cross a proposed partition $(S,\bar{S})$ takes $\Oh(n+m)$ time. For hardness, reduce from \textsc{Not-All-Equal-3-SAT} (\textsc{NAE-3SAT}), an $\mathsf{NP}$-complete variant of \textsc{3-SAT} in which each clause is satisfied when its three literals are not all assigned the same truth value (neither all true nor all false).
View the two sides $(S,\bar{S})$ of the cut as the two truth values.
Create $2n$ vertices, one for $x_i$ and one for $\bar{x}_i$ ($1\le i\le n$).
For each of the $m$ clauses, add a triangle on its three literal vertices (allowing parallel multiedges, which can be subdivided if a simple graph is desired). A triangle has at most $2$ of its $3$ edges cut, achieving $2$ if and only if its three vertices are not all placed on the same side (Figure~\ref{ch37:fig-maxcut-gadget}). To force $x_i$ and $\bar{x}_i$ onto opposite sides, join each pair $\{x_i,\bar{x}_i\}$ by $M=2m+1$ parallel edges. Separating all $n$ variable pairs earns $nM$ from these consistency edges alone; failing to separate even one pair yields at most
\begin{align*}
  (n-1)M + 2m
  &= nM - (2m+1) + 2m && \text{(since $M = 2m+1$ and $m$ triangles contribute $\le 2m$)} \\
  &= nM - 1 < nM.
\end{align*}
Hence any cut of size $\ge nM$ separates every pair $\{x_i,\bar{x}_i\}$, and a cut of size $k = nM + 2m$ exists if and only if all $m$ clause triangles simultaneously contribute $2$, which holds exactly when the \textsc{NAE-3SAT} formula is satisfiable.
\end{proof}

\begin{connectionbox}
Encoding $(S,\bar{S})$ by a vector $x\in\{-1,+1\}^n$ ($x_u=+1$ for $u\in S$, $x_u=-1$ for $u\in\bar{S}$) writes the cut size in terms of the graph Laplacian $\Lap$ (Chapter~31):
\[
  \frac{1}{4}\,x^\top \Lap x
  = \frac{1}{4}\sum_{\{u,v\}\in E}(x_u-x_v)^2
  = \text{number of edges crossing }(S,\bar{S}),
\]
since $(x_u-x_v)^2$ equals $0$ when $x_u=x_v$ and $4$ when $x_u\neq x_v$. Maximizing $\tfrac{1}{4}x^\top \Lap x$ over continuous unit vectors links cut size to the largest eigenvalue of $\Lap$ (Chapter~32). Allowing each vertex to hold its own unit vector on an $n$-dimensional sphere and splitting the sphere with a random plane through the origin gives the Goemans--Williamson semidefinite-programming algorithm, which achieves at least $0.878$ of the maximum cut in expectation (Chapter~38).
\end{connectionbox}

\textbf{Steiner Tree.} Given a graph $\Gph=(V,E)$ with nonnegative edge weights and a subset $R\subseteq V$
of required vertices called \emph{terminals}, a \emph{Steiner tree} is a minimum-weight connected subgraph containing all vertices of
$R$ (possibly routing through optional non-terminal ``Steiner'' vertices in $V\setminus R$). The decision problem asks whether a connecting tree of total weight $\le L$ exists. When $R=V$, this is the minimum
spanning tree problem (Chapter~6); when $\abs{R}=2$, it is single-pair shortest path (Chapter~7). For arbitrary $R\subseteq V$, \textsc{Steiner-Tree} is $\mathsf{NP}$-complete: one reduces from \textsc{Vertex-Cover} by making each edge of the cover instance a terminal that must be connected to a root through at least one of its endpoint vertices in $V$.

\begin{intuitionbox}
The two polynomial special cases of \textsc{Steiner-Tree} fix the vertex set in advance: MST uses every vertex ($R=V$), and shortest path needs no extra hubs when weights obey the triangle inequality ($\abs{R}=2$). Hardness arises from choosing \emph{which} subset of optional vertices in $V\setminus R$ to recruit as hubs
(Figure~\ref{ch37:fig-steiner}).
Taking an MST on $R$ under shortest-path distances gives a $2$-approximation, and linear-programming rounding improves the ratio to $\ln 4 + \eps \approx 1.39$ for any constant $\eps>0$ (Chapter~38).
\end{intuitionbox}

\section{The Boundary Between Easy and Hard}
\label{ch37:boundary}

Small changes in a problem statement ($2$
versus $3$, ``edge'' versus ``vertex,'' shortest versus longest) can flip a problem from linear time to
$\mathsf{NP}$-complete. We compare five pairs in detail; Table~\ref{ch37:tab-boundary} summarizes all seven boundaries encountered in this chapter.

\subsection{2-Coloring vs 3-Coloring}

\textsc{2-Coloring} runs in $\Oh(n+m)$ time: a graph is 2-colorable if and only if it is
\emph{bipartite}, which holds if and only if it contains no odd cycle (Chapter~1). A single BFS
assigns alternating colors $0$ and $1$ layer by layer and reports failure upon seeing an edge between two vertices of the same color
(Algorithm~\ref{ch37:alg-2col} and Figure~\ref{ch37:fig-2col}).

\begin{algorithm}[htbp]
\caption{\textsc{Two-Color}$(\Gph)$ -- bipartiteness by BFS}
\label{ch37:alg-2col}
\DontPrintSemicolon
\KwIn{Undirected graph $\Gph=(V,E)$.}
\KwOut{A proper 2-coloring, or \textsf{not 2-colorable}.}
$\mathrm{color}[v]\gets\textsf{none}$ for all $v$\;
\ForEach{vertex $s$ with $\mathrm{color}[s]=\textsf{none}$}{
  $\mathrm{color}[s]\gets 0$;\quad enqueue $s$\;
  \While{queue nonempty}{
    $u\gets$ dequeue\;
    \ForEach{neighbor $w$ of $u$}{
      \uIf{$\mathrm{color}[w]=\textsf{none}$}{
        $\mathrm{color}[w]\gets 1-\mathrm{color}[u]$;\quad enqueue $w$\;
      }
      \ElseIf{$\mathrm{color}[w]=\mathrm{color}[u]$}{
        \Return \textsf{not 2-colorable}\;
      }
    }
  }
}
\Return $\mathrm{color}$\;
\end{algorithm}

\begin{whybox}
With two colors, every step is forced: once $s$ receives color $0$, all of its neighbors
must receive $1$, their unvisited neighbors must receive $0$, and so on without branching.
An edge whose endpoints receive the same color appears if and only if the BFS tree paths to those endpoints plus that edge form an odd cycle.
With \emph{three} colors, propagation stops being unique: a vertex with one colored neighbor still has two legal colors left,
and those two-way choices allow the OR-gadget of \S\ref{ch37:coloring} to simulate \textsc{3-SAT}.
\end{whybox}

\subsection{2-SAT vs 3-SAT}

\textsc{2-SAT} (at most two literals per clause) runs in $\Oh(n+m)$ time (Chapter~5), whereas \textsc{3-SAT} is
$\mathsf{NP}$-complete. The algebraic difference lies in how clauses rewrite as implications:
\[
  (a \vee b) \;\equiv\; (\bar{a}\Rightarrow b) \wedge (\bar{b}\Rightarrow a),
  \qquad\text{whereas}\qquad
  (a \vee b \vee c) \;\equiv\; (\bar{a}\wedge\bar{b})\Rightarrow c.
\]
In \textsc{2-SAT}, each clause gives two ordinary directed arcs in the \emph{implication graph} on the $2n$ literals, and $\varphi$ is
satisfiable if and only if no variable $x_i$ lies in the same strongly connected component (SCC) as $\bar{x}_i$.

\end{intuitionbox}

\subsection{Shortest vs Longest Path}

As seen in \S\ref{ch37:longest}, shortest paths with nonnegative edge weights have optimal substructure
because cycles never shorten a walk, whereas longest \emph{simple} paths lose optimal substructure to the no-repeat
constraint (Figure~\ref{ch37:fig-longest-substructure}). On DAGs, where cycles are absent, longest path returns to linear time.

\subsection{Min-Cut vs Max-Cut}

\textsc{Min-Cut} is solvable in polynomial time via max-flow min-cut duality (Chapter~12) or Karger's contraction algorithm (Chapter~11), whereas
\textsc{Max-Cut} is $\mathsf{NP}$-complete (\S\ref{ch37:maxcut-steiner}).
Minimizing an $s$--$t$ cut can be relaxed from $\{0,1\}$ side assignments to continuous fractional variables in $[0,1]$ (a linear program) without changing the minimum value; maximizing a cut has no exact continuous relaxation known, because allowing fractional or vector assignments produces strictly larger objective values than any discrete partition $(S,\bar{S})$.

\subsection{Matching vs 3-Dimensional Matching}

Maximum matching in any graph runs in polynomial time via Edmonds' blossom algorithm (Chapter~17).
Its three-way generalization, \textsc{3-Dimensional-Matching}, gives three disjoint sets $X,Y,Z$ of size $n$ and a collection of allowed triples $T\subseteq X\times Y\times Z$, and asks whether there exist $n$ pairwise-disjoint triples in $T$ covering every element of $X\cup Y\cup Z$ once. Karp proved \textsc{3-Dimensional-Matching} is $\mathsf{NP}$-complete, and it serves as a standard starting point for reductions to \textsc{Steiner-Tree}, \emph{set cover} (choosing the fewest subsets from a family to cover a universe), and scheduling problems. Figure~\ref{ch37:fig-2d-vs-3d-matching} illustrates why augmenting paths rescue $2$D matching but fail in $3$D: the union of two ordinary matchings has degree at most $2$ at every vertex and decomposes into disjoint paths and even cycles, whereas overlapping triples in $3$D branch into conflict trees.

\section{What Hardness Means for Algorithm Design}
\label{ch37:design}

Proving that your problem is $\mathsf{NP}$-hard tells you to stop searching for a general exact polynomial-time
algorithm and choose one of five practical alternatives (Figure~\ref{ch37:fig-growth-rates} compares how their runtimes scale):

\begin{itemize}
  \item \textbf{Approximation} (Chapter~38). Settle for solutions guaranteed to lie within a factor $\rho$ of optimal.
        \textsc{Vertex-Cover} has a $2$-approximation (take both endpoints of every edge in a maximal
        matching); metric \textsc{TSP} has Christofides' $3/2$-approximation; \textsc{Max-Cut} has
        Goemans--Williamson's $0.878$-approximation. Not every problem cooperates: general \textsc{TSP} admits no constant-factor approximation, and
        \textsc{Clique} cannot be approximated within $n^{1-\eps}$ for any $\eps>0$ unless
        $\mathsf{P}=\mathsf{NP}$ (a consequence of the \emph{Probabilistically Checkable Proofs} (PCP) theorem, which strengthens Cook--Levin to show that even approximate satisfiability is hard).
  \item \textbf{Parameterization} (Chapters~24--25). Isolate the exponential growth in a parameter $k$ that stays small on your inputs. \textsc{Vertex-Cover}
        is fixed-parameter tractable (FPT) in $\Oh(1.27^k + kn)$ time via bounded-depth branching, solving covers of size $k\le 30$ quickly even on million-vertex graphs. \textsc{Clique} and
        \textsc{Independent-Set}, by contrast, are $\mathsf{W}[1]$-hard (the parameterized counterpart of $\mathsf{NP}$-hard, Chapter~25), so no $f(k)\cdot\poly(n)$ algorithm is expected.
  \item \textbf{Structural restriction.} Many $\mathsf{NP}$-complete problems run in polynomial time when inputs belong to a structured graph family: bounded-treewidth graphs (Chapter~24), planar graphs
        (Chapter~26, where Baker's BFS-layering method gives \emph{polynomial-time approximation schemes} (PTASs) achieving $(1+\eps)$-approximations for any fixed $\eps>0$), and interval, chordal, or perfect
        graphs (Chapter~30, where coloring and maximum clique are polynomial-time).
  \item \textbf{Exact exponential algorithms.} When $n$ is modest, dynamic programming and pruning beat naive enumeration. Held--Karp DP tracks the shortest path through each subset $S\subseteq V$ ending at each vertex $v$, solving \textsc{TSP} in $\Oh(2^n n^2)$ time rather than $\Oh(n!)$; \emph{branch-and-bound} search explores partial tours in a tree and prunes any branch whose lower bound already exceeds the best tour found so far, handling thousands of cities in practice.
  \item \textbf{Heuristics and SAT/ILP solvers.} Encode the graph problem back into \textsc{SAT} or \emph{integer linear programming} (ILP, optimizing a linear objective under linear inequalities with integer variables; called \emph{mixed-integer programming}, MIP, when only some variables must be integers). Industrial \emph{conflict-driven clause learning} (CDCL) SAT solvers (which record new clauses whenever a search branch hits a contradiction) and MIP engines routinely solve large structured instances despite worst-case exponential hardness.
\end{itemize}

\section{Historical Context and Controversies}
\label{ch37:history}

\begin{historybox}
The idea that natural computational problems might resist fast algorithms altogether traces back to Kurt G\"odel. In a 1956 letter to John von Neumann, G\"odel asked whether testing if a mathematical statement has a proof of length $n$ could be done mechanically in $\Oh(n)$ or $\Oh(n^2)$ steps, observing that such a procedure would automate mathematics. Through the 1950s and 1960s, operations-research groups kept hitting the same wall: linear programming, minimum spanning trees, matchings, and shortest paths yielded polynomial-time algorithms, yet modest changes, such as requiring integer variables, visiting every city once, or finding a maximum clique, defeated every polynomial-time attempt.

In 1971, Stephen Cook defined the class $\mathsf{NP}$ and proved that Boolean Satisfiability (\textsc{SAT}) is $\mathsf{NP}$-complete by encoding the computation table of any polynomial-time verifier as a Boolean formula. Independently in the Soviet Union, Leonid Levin published an equivalent completeness theorem for universal search problems in 1973. In 1972, Richard Karp showed that \textsc{SAT} reduces in polynomial time to $21$ combinatorial problems, including \textsc{Vertex-Cover}, \textsc{Clique}, \textsc{Ham-Cycle}, $c$-\textsc{Coloring}, \textsc{Steiner-Tree}, and \textsc{Max-Cut}, demonstrating that hardness was shared across discrete optimization rather than confined to formal logic.

Before Cook, Levin, and Karp, algorithm designers had no way to distinguish ``I have not found a fast algorithm yet'' from ``no fast algorithm exists unless $\mathsf{P}=\mathsf{NP}$.'' Establishing $\mathsf{NP}$-completeness redirected research toward approximation ratios, parameterized algorithms, special graph classes, and industrial SAT/MIP solvers, while leaving $\mathsf{P}$ versus $\mathsf{NP}$ as the central open problem of theoretical computer science.
\end{historybox}

\subsection{What We Can Now Do and Its Limitations}
\begin{connectionbox}
\textbf{What this chapter adds to the toolkit:}
\begin{itemize}
  \item \emph{Gadget reductions:} Starting from \textsc{3-SAT} (whose Cook--Levin proof from Turing-machine computation tables appears in the companion algorithms book), gadget constructions prove $\mathsf{NP}$-completeness across independent sets, covers, cliques, coloring, Hamiltonian cycles, \textsc{TSP}, longest paths, \textsc{Max-Cut}, and \textsc{Steiner-Tree}.
  \item \emph{Boundary diagnosis:} Checking whether local constraints force unique propagation (as in $2$-coloring and \textsc{2-SAT}) or leave branching choices helps predict whether a new variant lies in $\mathsf{P}$ or is $\mathsf{NP}$-hard.
\end{itemize}

\textbf{Limitations to keep in mind:}
\begin{itemize}
  \item \emph{Worst-case classification:} $\mathsf{NP}$-completeness measures worst-case scaling. Many real-world instances of $\mathsf{NP}$-hard problems carry enough structure for modern CDCL SAT solvers or MIP packages to solve them quickly.
  \item \emph{Approximation is not preserved by $\le_p$:} An exact polynomial-time reduction preserves yes/no answers, not approximation factors. Although \textsc{Vertex-Cover} and \textsc{Independent-Set} convert into each other via $C = V\setminus S$ (Lemma~\ref{ch37:lem-triangle}), a $2$-approximate cover of size $0.9n$ when the minimum cover has size $0.45n$ leaves an independent set of size $0.1n$ instead of $0.55n$, destroying the ratio; likewise metric \textsc{TSP} admits a $3/2$-approximation while general \textsc{TSP} admits no constant-factor approximation unless $\mathsf{P}=\mathsf{NP}$.
\end{itemize}

\textbf{Where we go next:}
\begin{itemize}
  \item Chapter~38 (Approximation Algorithms on Graphs) trades exactness for provable polynomial-time guarantees: greedy set cover, linear-programming rounding for vertex cover, Christofides' $3/2$-approximation for metric \textsc{TSP}, and Goemans--Williamson's $0.878$-approximation for \textsc{Max-Cut}.
  \item Chapter~39 (Dynamic Graph Algorithms) studies maintaining connectivity, spanning forests, and shortest paths as edges are inserted and deleted online without recomputing from scratch.
\end{itemize}
\end{connectionbox}

\section{Exercises}
\label{ch37:exercises}

\begin{exercise}[Direction discipline]
\label{ch37:ex-direction}
A classmate tries to prove a new graph problem \textsc{Foo} is $\mathsf{NP}$-hard by reducing \textsc{Foo} to \textsc{Clique}: ``encode any instance of \textsc{Foo} as a \textsc{Clique} instance in polynomial time; since \textsc{Clique} is $\mathsf{NP}$-hard, \textsc{Foo} must be $\mathsf{NP}$-hard too.'' Explain in one paragraph why this arrow ($\textsc{Foo}\le_p\textsc{Clique}$) points the wrong way, what it does prove about \textsc{Foo}, and which reduction direction is needed instead.
\end{exercise}

\begin{exercise}[Complementarity by hand]
\label{ch37:ex-complement}
Take the $5$-cycle $C_5$. (a) Find a maximum independent set and a minimum
vertex cover of $C_5$, and verify $\abs{\text{IS}}+\abs{\text{VC}}=5$. (b) Draw
$\overline{C_5}$ and find a maximum clique; confirm its size equals the maximum
independent-set size of $C_5$ via Lemma~\ref{ch37:lem-triangle}.
\end{exercise}

\begin{exercise}[Run the IS gadget]
\label{ch37:ex-isgadget}
Apply Algorithm~\ref{ch37:alg-is} to
$\varphi=(x_1\vee x_2\vee \bar{x}_3)\wedge(\bar{x}_1\vee x_2\vee x_3)\wedge
(x_1\vee \bar{x}_2\vee x_3)$. Draw $\Gph_\varphi$ (three triangles plus conflict edges),
find an independent set of size $3$, and read off the corresponding satisfying assignment.
\end{exercise}

\begin{exercise}[Why each clause must be a triangle]
\label{ch37:ex-trianglecount}
In the proof of Theorem~\ref{ch37:thm-is}, an independent set $S$ of
size $m$ had to take \emph{exactly} one vertex from each clause triangle. Prove this
step: writing $s_j = \abs{S\cap V(C_j)}$ for the number of vertices chosen in clause $j$, show that $s_j\le 1$ for all $1\le j\le m$ together with $\sum_{j=1}^m s_j = m$ forces $s_j=1$ for every $j$. Then show by counterexample where the reduction would fail if each $3$-literal clause were wired as a $2$-edge path $v_{j1}\text{--}v_{j2}\text{--}v_{j3}$ instead of a triangle.
\end{exercise}

\begin{exercise}[Metric vs general TSP]
\label{ch37:ex-tsp}
(a) Verify that the $1$/$2$ distance function in Theorem~\ref{ch37:thm-tsp} satisfies the
triangle inequality $d(i,k)\le d(i,j)+d(j,k)$ for all $i,j,k$. (b) Using the distances $1$ (for edges) and $n\rho+1$ (for non-edges) from the box after
Theorem~\ref{ch37:thm-tsp}, prove in detail that a polynomial-time $\rho$-approximation algorithm for general \textsc{TSP} (for any constant $\rho\ge 1$) would imply $\mathsf{P}=\mathsf{NP}$. (c) Why does this reduction fail to rule out Christofides'
$3/2$-approximation for metric \textsc{TSP}?
\end{exercise}

\begin{exercise}[Longest path on a DAG]
\label{ch37:ex-dag}
Give an $\Oh(n+m)$ dynamic-programming algorithm for finding a longest path in an $n$-vertex, $m$-edge DAG. Then exhibit a directed graph with a cycle on at most $5$ vertices where applying your recurrence along an arbitrary vertex order returns a wrong answer for longest simple path, and identify the step that required acyclicity.
\end{exercise}

\begin{exercise}[2-SAT implication graph]
\label{ch37:ex-2sat}
Decide $(x_1\vee x_2)\wedge(\bar{x}_1\vee x_3)\wedge(\bar{x}_2\vee\bar{x}_3)\wedge
(x_2\vee x_3)$ by building its $6$-vertex implication graph, computing
its strongly connected components, and checking that no variable $x_i$ shares a component
with $\bar{x}_i$. Read off a satisfying assignment from the reverse
topological order of the component DAG (Chapter~5).
\end{exercise}

\begin{exercise}[Coloring lifts 3 to $c$]
\label{ch37:ex-clift}
Prove that \textsc{$c$-Coloring} is $\mathsf{NP}$-complete for every fixed integer $c\ge
3$ by reducing from \textsc{3-Coloring}: add $c-3$ new vertices forming a clique, each
joined to every original vertex, and show that the augmented graph is
$c$-colorable if and only if the original graph is $3$-colorable.
\end{exercise}

\begin{exercise}[Break a gadget]
\label{ch37:ex-break}
In the 3-coloring reduction (\S\ref{ch37:coloring}), suppose you \emph{forgot} to
make each clause-output vertex $r_2$ adjacent to the false vertex $F$ (you only joined $r_2$ to
$B$). Construct a small unsatisfiable \textsc{3-SAT} formula whose resulting graph is still
properly 3-colorable under this broken gadget, showing why the edge $r_2F$ is essential.
\end{exercise}

\begin{exercise}[FPT is not preserved by complementation]
\label{ch37:ex-fpt}
\textsc{Vertex-Cover} parameterized by cover size $k$ has an $\Oh(2^k(n+m))$
bounded-search-tree algorithm: pick any uncovered edge $uv$ and recursively branch on placing
$u$ or $v$ into the cover. (a) Write this algorithm in pseudocode and prove both correctness and
the $\Oh(2^k(n+m))$ runtime bound. (b) Explain why Lemma~\ref{ch37:lem-triangle}
($\abs{\text{IS}}=n-\abs{\text{VC}}$) does \emph{not} convert this into an $f(k)\cdot\poly(n)$ algorithm
for \textsc{Independent-Set} parameterized by independent-set size $k$.
\end{exercise}

\begin{exercise}[Max-Cut on small graphs and local search]
\label{ch37:ex-maxcut}
(a) Compute the maximum cut size of $K_3$ and of $K_4$ by hand. (b) For the $4$-cycle
$C_4$, exhibit a cut crossing all $4$ edges. (c) Show that
greedy local search (repeatedly flip any vertex to the opposite side if doing so strictly increases the number of cut edges) terminates in at most $\abs{E}$ flips at a cut of size at least $\abs{E}/2$ (a $2$-approximation), and give a small graph with a locally optimal partition whose cut is strictly smaller than the global maximum cut.
\end{exercise}

\begin{exercise}[Reduction transitivity in practice]
\label{ch37:ex-transitive}
Compose the reductions of Theorem~\ref{ch37:thm-ham} and Theorem~\ref{ch37:thm-tsp} to describe a single polynomial-time map
from \textsc{3-SAT} to metric \textsc{TSP}. Using the undirected vertex-expansion in Theorem~\ref{ch37:thm-ham} ($2m$ vertices per variable chain, $m$ clause vertices, and endpoints $s,t$, each expanded into a $3$-vertex undirected gadget), express the resulting number of cities $N$ and tour budget $L$ in terms of $n$ and $m$, and verify that the composed reduction runs in polynomial time.
\end{exercise}
